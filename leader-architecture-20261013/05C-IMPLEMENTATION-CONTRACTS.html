Phụ lục 05C. Interfaces, record quyết định và thuật toán dùng chung

Phụ lục này làm rõ cách triển khai tài liệu 05 trong các project hiện có. Tên type là hợp đồng đề xuất; adapter có thể dùng record hiện hành tương đương. Không tạo pipeline song song. Các quy tắc kết cấu lấy từ 01/05A/05B hoặc record đã duyệt trong 04. Các lựa chọn tổ chức phần mềm dưới đây là quyết định kiến trúc của project leader ngày 13/10/2026, không phải quy tắc kết cấu suy từ PDF.

C.3. Record để chủ nhiệm chốt 23 NeedsRule

Mỗi record có header chung: RuleId, Version, Scope{Profiles,Components,Shapes,Conditions}, SourceRefs[], DecisionStatus{Proposal,Approved,Rejected}, Approver, ApprovedAt, SupersedesVersion?, ContentHash. ApprovedAt/Approver thiếu thì record vẫn chưa Approved. Parameter vật lý có unit; maps enum phải phủ đủ scope đã công bố. Không tạo enum Other rồi fallback sang C/U/Z gần giống.

C.4. Identity, quantity và hash

PhysicalId = Encode(ManholeId, AssemblyId, ComponentId, PanelInstanceId?,
                    Face, Layer, Direction, Family, OriginalStationId,
                    RetainedIntervalOrdinal)
OriginalStationId = Encode(HostFrameId, GridRuleVersion, Direction, OriginalGridIndex)

sort retained intervals by start distance along original parent path
assign ordinal before view projection
never allocate PhysicalId from DisplayMark or order of labels

emit one occurrence per physical steel piece
for n panels: expand PanelInstanceId for each panel before canonical/group accounting
if calculator emits a per-panel prototype:
    expand multiplicity exactly once at S4 boundary
    record expansion receipt and prototype -> physical occurrence IDs
do not multiply SL/TDAI again in S8 or for duplicate views

Nguồn: owner mô hình ba lớp và quantity/member invariants; EX-045/046/047 về panel; encoding/expansion boundary là quyết định kiến trúc. Canonical row chứa những occurrences cùng shape/dimensions/basis; presentation group có thể gộp nhiều canonical rows tương thích theo owner nhưng giữ MemberIds đầy đủ.

Hash payload dùng canonical serialization: ordinal dictionary keys; list theo stable ID nếu list là tập, giữ nguyên order nếu là path/segment sequence; invariant numeric representation và unit; null tường minh; UTF-8. PhysicalHash loại layout/label positions/display names; PresentationHash bao gồm chúng. ReceiptHash bao gồm RunId/source/build/rule versions. Không dùng hash DXF/DWG bytes để kết luận geometry bất biến vì handles/save metadata có thể đổi; geometry comparison dùng native normalized semantic manifest có handle map.

C.5. Cắt thanh và phân vùng ngữ nghĩa

Nguồn: OpeningClipper/ClipResult, owner bốn vùng, G500-CUT-MEMBERS-AUDIT; interval operations dưới đây là triển khai hình học của các định nghĩa đó. Không thêm bán kính fixture.

for parent bar on a resolved host frame:
    cuts = []
    for opening that actually intersects this bar's depth/support:
        exclusions = resolve contour and clearance with approved NR-01 convention
        intersections = intersect analytic parent path with exclusions
        sort by parent-path parameter; pair entry/exit using inside predicate
        add closed removed intervals with OpeningId and crossing roles
    merged = union sorted removed intervals under approved numerical policy
    retained = support interval minus merged
    discard only zero-length intervals under that same topology policy
    emit retained intervals, parent/station/OpeningIds/end roles
    keep removed ledger even when the bar is completely removed
    verify retained+removed covers preclip run with no overlap

RegionRole lấy trong host convention nhìn từ trong ra: một opening và một direction có các retained pieces phía trái/phải hoặc trên/dưới. Chỉ dùng approved convention để ánh xạ sang T1A/T1B/T2A/T2B; mirror view không đổi region. Nhiều openings: lưu sorted OpeningRegionSet và quan hệ Before/Between/After, chưa có vocabulary NR-12 thì preview có GroupId nhưng Final bị chặn ở naming. Không gán vùng bằng tọa độ trên sheet.

Polygon có lỗ lấy inside/outside từ Outer+InnerLoops và ownership depth; không bbox clipping. Vòng tròn dùng nghiệm analytic 05.7. Đối với cung cong, dùng arc parameter và cùng interval semantics; planner chưa có intersection capability phải trả Unsupported kèm SubjectId, không discretize rồi cấp fabrication length giả.

C.6. Đặt nhãn và phân trang hữu hạn

Nguồn: C06/paper metrics; PDF leader/callout tables; NR-16/22. Thuật toán search là lựa chọn phần mềm, không suy source offsets thành hằng số chung.

resolve complete label text/attributes before measuring ink
generate candidate lanes from recipe.AllowedSides and approved paper offsets
for lane in deterministic priority order:
    project obstacle ink intervals onto lane
    expand each interval by approved PaperInkGap
    subtract from allowed lane interval
    enumerate preferred anchor projection and free-interval endpoints
    place label using its real port and ink envelope
    choose route from target/collector branches with approved elbow topology
    validate member associations and route-vs-text keepouts
    first valid candidate wins; record rejected obstacle IDs
if no candidate:
    expand the view bundle's declared external ink area as allowed by recipe
    recompute once for that finite candidate set
if still no candidate: LAYOUT_ANNOTATION_NO_FIT

Không thêm lần thử hoặc bước trượt tùy ý. Search không tự tăng vô hạn vùng view; recipe/presentation profile phải khai báo vùng được phép. Cho phép route chạm label port và cắt projected bar tại target; keepout checker phải có các exception có ID này, tránh báo mọi giao tuyến là lỗi.

S9 đo cả geometry+titles+DIM+labels+TK, giữ semantic group cùng nhau. Mỗi nhóm đặt trong frame theo recipe; hết chỗ thì mở page mới cùng scale. Tập scale Auto chỉ là danh sách từ NR-22; mọi lần đổi S phải dựng lại paper metrics và ink rồi kiểm gate. View đơn không fit phải Block với required/available bounds, không tạo vòng mở page rỗng.

C.7. Write, batch và acceptance không nuốt lỗi

for each selected row:
    create RowReceipt before any calculation
    run required stages with immutable source/build/rules
    store each diagnostic and last successful receipt
    if blocked: mark row Blocked; independent rows continue
    if cancellation requested: mark this and remaining rows explicitly

for each Ready write unit in a healthy CAD document:
    preflight all assets/schema/ownership and migration effects
    transaction: append or replace only owned generation entities
    commit only when unit invariants and repository records agree
    failure: rollback unit; record handles affected and recovery result

save output copy; reopen; read native values/geometry/attrs/styles
plot only registered frame windows with compatible approved CTB/STB
for every required acceptance subject:
    persist expected, actual, unit, tolerance rule, source, native handles, evidence
    missing evidence or approval -> NotRun/Blocked, never Passed
    numerical mismatch -> Failed
    visually reviewed region -> attach region verdict and reviewer
batch Complete only if every selected valid row has every required gate Passed

Row invalid không phải N/A: batch phải báo có lỗi input. N/A chỉ dùng cho view/feature không được yêu cầu theo input và rule đã rõ. Ca không đúng numerical bundle nguồn dùng Excel/rule làm expected; PDF mẫu dùng recipe/semantic evidence. Source khác không được dùng làm lý do cho output mất label, sai geometry hoặc co sản phẩm.

Các record thực tế phải giữ field types ở C.1/C.2 và 06.4; không tạo Passed:true chung thay các verdict. Acceptance DWG/PDF và update/recovery trong 06 là công việc sau implement, chưa được chạy bởi việc lập hồ sơ này.
